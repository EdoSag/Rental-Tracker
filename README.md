# ניהול שכירות – Rental Tracker

אפליקציית Android (Flutter) בעברית לניהול הכנסות והוצאות של בית עם 4 יחידות להשכרה.
עובדת offline לגמרי: כל הנתונים והתמונות נשמרים בטלפון בלבד (SQLite), בלי שרת, בלי הרשמה ובלי פרסומות.

## התקנה בטלפון

1. בטלפון, פתח את דף ה-[Releases](../../releases/latest) של הריפו והורד את קובץ ה-`.apk` האחרון.
2. פתח את הקובץ שהורד. אם Android מבקש, אשר "התקנה ממקורות לא ידועים" לדפדפן / לקבצים.
3. לחץ "התקן". אם Play Protect מזהיר על אפליקציה לא מוכרת, בחר "פרטים נוספים" ← "התקן בכל זאת".
4. עדכון לגרסה חדשה: מורידים את ה-APK החדש ומתקינים מעל הקיים. הנתונים נשמרים.

> חשוב: אין לגבות את הנתונים לענן אוטומטית. מומלץ לעשות מדי פעם **הגדרות ← ייצוא גיבוי (zip)** ולשמור ב-Drive או במייל.

## מסכים

- **חודש** – בורר חודש, כרטיס לכל שוכר (קריאות חשמל ומים, ארנונה, שכירות, "שולם", צילומי שעונים), כרטיס החיובים שלי מהעירייה והחברות, ותוצאות החודש שמתעדכנות תוך כדי הקלדה.
- **סיכום** – סה"כ כללי, חלוקת רווחים, סיכום שנתי, טבלה חודש־חודש, וייצוא לאקסל.
- **הגדרות** – מחירי חשמל ומים, דמי ניהול, שכר דירה לכל שוכר, אחוזי השותפים, גיבוי ושחזור.

## זיהוי קריאה מתמונה

אחרי הוספת צילום שעון (מהגלריה או מהמצלמה) האפליקציה מזהה את המספרים בתמונה **בטלפון עצמו** (Google ML Kit, מודל מובנה, בלי אינטרנט) ומציעה את הקריאה המתאימה ביותר:
- בוחרת חשמל או מים לפי היחידות בתמונה (kWh / m³ / קוט"ש / מ"ק) או לפי הקריאה האחרונה של כל שעון.
- מדרגת את המספרים לפי הקרבה לקריאה האחרונה (מעליה, בטווח סביר), מתעלמת מתאריכים, שעות ומספרים סידוריים, ומטפלת בספרות אדומות (עשרוניות) בשעוני מים.
- מציגה את ההצעה לאישור בלחיצה אחת, עם אפשרות לבחור מספר אחר או לתקן ידנית.

לתמונה קיימת: פותחים אותה ולוחצים על אייקון הסריקה למעלה.

## לוגיקת חישוב

לכל שוכר בכל חודש:
- צריכה = קריאה נוכחית − קריאה אחרונה (לא פחות מ-0). חיוב = צריכה × מחיר.
- "קריאה אחרונה" = הקריאה הנוכחית האחרונה שהוזנה לאותו שוכר בחודש מוקדם יותר (ניתן לעריכה ידנית; מחיקת השדה מחזירה לערך האוטומטי).
- אין קריאה קודמת ← "קריאה ראשונה – בסיס", ללא חיוב צריכה.
- סה"כ לשוכר = שכירות + חשמל + מים + ארנונה.

לכל חודש: הכנסות = סכום השוכרים; דמי ניהול = הכנסות × אחוז; הוצאות = חשמל + מים + ארנונה + אחרות + דמי ניהול; רווח נקי = הכנסות − הוצאות; חלק שותף = רווח נקי × האחוז שלו (בלי קשר לסימון "שולם").

## פיתוח

```bash
flutter pub get
flutter test          # בדיקות עם נתוני דוגמה: 3 חודשים, 4 שוכרים
flutter build apk --release
```

מבנה הקוד:

| קובץ | תפקיד |
|---|---|
| `lib/models.dart` | מודלים, שמות שוכרים ושותפים, חודשים |
| `lib/calc.dart` | כל החישובים (טהור, נבדק ב-`test/calc_test.dart`) |
| `lib/db.dart` | שמירה ב-SQLite |
| `lib/state.dart` | מצב האפליקציה ושמירה אוטומטית |
| `lib/screens/` | שלושת המסכים |
| `lib/services/excel_export.dart` | ייצוא xlsx (RTL, שני גיליונות) |
| `lib/services/backup.dart` | גיבוי ושחזור zip |
| `lib/services/meter_ocr.dart` | זיהוי טקסט בתמונה (ML Kit, offline) |
| `lib/services/reading_extractor.dart` | בחירת הקריאה מתוך הטקסט (נבדק ב-`test/reading_extractor_test.dart`) |

### בנייה וחתימה ב-GitHub Actions

כל push ל-`main` בונה APK (`.github/workflows/build-apk.yml`), מריץ את הבדיקות ומפרסם Release.
החתימה נעשית עם מפתח קבוע שנשמר ב-Secrets של הריפו:

- `KEYSTORE_BASE64` – קובץ ה-keystore בקידוד base64
- `KEYSTORE_PASSWORD` – הסיסמה (alias: `rental`)

בלי ה-Secrets נבנה APK לבדיקה בלבד, חתום במפתח זמני (לא מתפרסם כ-Release).
